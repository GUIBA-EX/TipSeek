# HX50：完整 CDS 缺失排查、reads 审计与多 contig 修正

日期：2026-10-11。本阶段在原海星 SCO 测试上继续实现，完整 CDS 仍为 0，但编码证据找回明显改善。未把参考覆盖并集、补 N 或缺乏冲突 reads 当作完整 CDS 或真实连接。

## 找到的原因与修正

1. **原来的“穷尽种子”仍只搜索参考核苷酸种子。** 跨物种参考下，有些已招募 reads 能比对到蛋白，却没有精确核苷酸起点。直接检查重过滤后的真实 reads，例如 `SCO_AST_006612_OG0011917` 有约 96.69% 的参考残基证据，而原组装的同口径证据仅 174/665。现在 exon 模式也访问高支持、无参考锚点的 read-graph 节点，新增片段只沿非分叉路径延伸，遇到分叉/环就停止。普通 gene 模式不改变。该家族的新 miniprot 编码证据为 654/665，exonerate-rs 为 653/665；这仍是多片段并集。
2. **固定的短重叠上限挡住真实组装片段。** k=51 的图片段可能共享约 50 nt，旧的 12 aa 上限会拒绝这类连接。参考 HybPiper 的 query 坐标重叠裁剪，以及 Captus 的顺序与兼容性检查，改为要求对应 CDS 逐碱基一致后只裁剪一次。不同序列、无法对应编码坐标的 indel 路径仍不裁剪。参考顺序不证明物理连接，竞争路径仍保留为歧义。
3. **整段 contig 的未建模尾部会干扰重注释。** 内部连接只保留模型周围最多 120 nt 的真实侧翼，最外两端保持原序列。原始坐标记录在 `join_sources.tsv`。补 N 仍必须完全位于内含子内，所有来源保留编码支持，并且重新获得完整合格模型才能接纳。
4. **缺少可审查的 reads 支持和失败原因。** 新增家族级 reads 索引、每条链相邻来源的配对审计、逐参考的完整度阻碍表。借鉴 HybPiper 的外显子内、不对称错配检查，但不声称复现其 BBMap 全部能力。

本地参考文件为 `Captus/captus/bioformats.py`（`parse_model`、`calc_prot_len_matched`、DNA 分支 `greedy_assembly_partial_hits`）及 `HybPiper/hybpiper/exonerate_hits.py`（重叠裁剪、stitched contig、chimera warning）。独立实现 Rust 逻辑；参考文件摘要保存在 JSON 中。

### 为什么完整 CDS 还是 0

`completion_audit.tsv` 的区间并集是**允许内部 query 缺口的覆盖上界**，专门用于排除“即使放宽也不够”的情况，与上表严格残基覆盖不同。

- 对 ppect 参考，miniprot 的 9/12 家族连区间并集上界也不到 80%；exonerate-rs 为 5/12。
- 上界达标也不代表有完整链。两后端的 12/12 家族都没有覆盖足够的可用干净链；其中各有 10 个家族存在竞争链记录。部分搜索超限，不能把截断搜索的赢家当作已消除歧义。
- miniprot 上界达标的三个家族 `004850`、`006503`、`006612`，最佳链分别只覆盖 363/944、107/387、472/665 aa。重叠序列冲突、内部 query 缺口/结构问题、竞争模型及端点缺失不能通过简单累计覆盖消除。
- 本次真实 reads 数据没有链进入补 N 完整重注释尝试，阻碍发生在来源和链选择阶段，不能归因于补 N 长度不够，也不能靠加 N 提高完整度。

没有降低完整 CDS 标准，也没有恢复微外显子推断。

## reads 支持：做了什么，不能证明什么

读取 `样本/filtered_pe/家族_1、_2`，实际检查 **21,942 对**招募 reads。对所有原始候选同时定位，避免只对待拼接的两段定位而制造唯一性。两后端共用同一 DNA 候选，因此审计汇总一致：580 对两端可唯一全长定位；去除相同位置/方向的重复后，有 27 对跨 contig 片段。

但这些片段没有为被评估的链边提供足够的“双方外显子内、方向正确、低错配且至少两个不同位置 pair”的支持。两后端的边状态记录均为 `insufficient_read_evidence`，**不等于连接错误，也不等于验证通过**。无 reads 冲突告警不能作为零错误合并率。

当前检查的明确范围：

- reads 至少 90 nt，全长无 indel，最佳位置最多 4 个替换，与次优位置至少差 2 个替换。15-mer 种子过度重复或候选位置超限时不判断唯一。
- 全家族索引只建一次；相同配对位置/方向去重。两端都必须完全处于相应来源的外显子内，在定向片段中相向。
- 至少五个去重 pair 出现“一端全匹配、另一端 3–4 个替换”，且数量超过低错配支持，才发出 `discordant_read_warning` 并阻止该链导出/自动拼接。方向冲突单独报告。
- 不建模碱基质量、indel 或插入片段长度；短于 read 的 contig、短外显子及跨剪接 reads 的支持能力有限。短 reads 本来就可能无法桥接超长内含子，因此没有桥接不是反证。
- GM2 没有原始 read 名称，依赖本流程保留的配对顺序并检查数量；FASTQ 同时检查名称和数量。

缺少同个体基因组、长 reads 或已验证连接，真实错误合并率仍记为 **null**。`physical_linkage=unverified` 保持不变。

## 性能与敏感性取舍

新增无参考锚点候选先进行内置六读框预筛：一个 10 aa 连续窗口至少 8 个一致残基，双方窗口各至少四种氨基酸。仅作用于新增、明确标记为 `assembler_seed_position=-2` 的片段，旧参考锚定候选及没有这种来源标记的外部输入不受影响；不依赖 miniprot，可用于独立 exonerate-rs 后端。

这是一项保守的候选限制，不证明未通过的片段非编码。相对未要求四种残基的 unitig 中间版本，miniprot 外显子数量仍为 106/185，平均 CDS 证据覆盖从 71.24% 变为 71.14%（约少 0.10 个百分点）。只有低复杂度或不足 10 aa 连续编码证据的独立救援片段可能被漏掉；原始序列保留，可审查 `protein_screen_rejected`。

性能改动包括非分叉路径恢复、按 seed 索引标记已访问节点、缓存链覆盖分数，以及按候选的有界进程并行。每候选一个线程，最多 64 个候选同时执行，结果按固定顺序汇总。

| 本机单次观察 | 耗时 |
| --- | ---: |
| 直接扩大起点并枚举分支的中间版组装 | 10.82 秒 |
| 最终非分叉救援组装 | **1.11 秒** |
| 最终同候选 miniprot，1 worker | 37.07 秒 |
| 最终同候选 miniprot，8 workers | **18.10 秒** |
| 最终 exonerate-rs，8 workers | **185.39 秒** |

miniprot 串行与并行比较了 **5,237 个结果文件/规范化审计文件，全部一致**。命令与 worker 元数据不参与内容一致比较，reads 根目录前缀被规范化；模型、CDS、其他序列和链审计均比较。

这些是本机单次结果，不是统计显著的速度排名。新流程处理的候选与信息量远多于前阶段（215 个候选，miniprot 约 6.15 秒、串行 Exonerate 约 81.02 秒），**仍不能宣称端到端“只能比旧版快”**。若干被后续实现替代的串行 Exonerate 实验主动取消，没有把其不完整耗时当作基准。

## 对照与回归

最终 **323 项 workspace 测试通过**，Clippy 全目标检查通过，release 构建和 Python 验证脚本编译检查通过。新增/扩展测试覆盖：无参考种子的短片段、分叉与环停止、长一致重叠裁剪及冲突拒绝、双端定位唯一性与方向、PCR 位置去重、外显子边界过滤、错配告警、配对损坏、GM2 序列解码、reads 目录防覆盖、候选预筛的全部两替换位置组合，以及独立 exonerate-rs 串行/并行等价与失败处理。

同一 12 个真实参考基因组来源的控制片段再次验证：miniprot 有 9 个未验证 CDS 假说，exonerate-rs 有 5 个及 1 个歧义结果；5/3 次补 N 尝试均被结构标准拒绝。这是基因组片段对照，不是 reads 组装真值。已有三片段 45/10/45 aa 正对照可通过完整重注释；跳过中间片段等负对照仍被拒绝。
