# 外显子注释采用 GeneMiner2 式 SCO 调度

已停止此前 HX50 7,006-SCO 全库测试，保留原始招募、组装、候选和已完成的部分注释。此次修改只在 12 个既定海星 SCO 上验证，没有自动恢复全库任务。

参考 GeneMiner2 `main_assembler.py` 中对每个 gene 提交任务的 `Pool.apply_async`，以及 `main_refilter_new.py` 的 `Pool.imap_unordered`，将外显子注释改为按样本和 SCO 领取任务。Rust 工作线程处理完整 SCO，并在完成后立即取下一项；每次外部比对单线程，无需引入 Python 运行时。

`-p` / `--threads` 是共享 CPU 并发预算，最多 64。队列充足时并行不同 SCO；收尾时剩余 SCO 可以借用空闲预算并行处理候选。候选宽度取 `floor(CPU预算 / 剩余任务数)`（至少 1），剩余数包含排队任务且只减不增，已有批次使用此前较小的额度，因此不会将两层并行数量相乘。单线程调用保留直接串行执行。

每项任务有独立目录。候选和参考通过只读硬链接接入，跨文件系统时回退到复制；样本装配审计仅扫描一次，再按 SCO 分配，避免每个任务重读全库表。合并时按样本、SCO、候选的原顺序处理文件；共享参考审计去重，重复表头检查一致性，各样本的同 SCO FASTA 保留独立记录。成功时移动独占文件并删除临时任务目录，避免复制大批比对结果。任务失败会停止领取新任务并保留临时证据，原始输入不被修改。

实际调度见 `manifest/execution.tsv`，`geneminer2_family_queue_shared_budget` 表示两层共用一个预算；两个 workers 字段不相乘。日志每完成 100 个 SCO 或全部完成时记录进度。

## 真实数据验证

继续使用 HX50 12-SCO 面板的同一批已组装候选、配对招募 reads 和用户指定的 `/home/yasuda2/starsco/geneminer_sco_refs/fasta`；固定 ppect 坐标参考，两种后端各使用 8 个 CPU 预算槽。

| 后端 | 旧候选批次调度 | 新 SCO 队列和共享预算 | 本次缩短 |
|---|---:|---:|---:|
| miniprot | 18.405 s | 13.981 s | 24.0% |
| exonerate-rs | 179.570 s | 137.421 s | 23.5% |

时间为单次同机测量，不能保证所有数据集都有同样加速。纯 SCO 队列在小面板收尾时会因长任务空闲其他核，初次 miniprot 测量为 20.239 s；因此最终版本增加共享预算收尾。初次 Exonerate 实验未完成并已取消，不列为完整性能结果。

miniprot 比较 6,510 个文件，Exonerate 比较 19,844 个文件，集合和内容一致，包括标准化模型、SCO/CDS/蛋白、外显子和内含子、reads/图/竞争模型审计以及原始比对。仅排除调度元数据、命令溯源和外部 stderr（含路径及耗时）；Exonerate 参数中的任务路径归一，状态首行保持比较、耗时行排除。未改变模型接纳或恢复碱基，外显子找回率也没有因调度修改而变化。

工作区 331 项测试通过，包含多样本、多 SCO 的串行/并行结果与参考审计去重核对；Clippy、release 构建、格式和差异检查通过。详细命令、源文件校验和、对比清单见 [JSON 报告](exon-family-scheduler.json)。
